# 硬件接线（Embedded wiring）

给嵌入式开发用的接线网表：**一份 JSON 既是 Agent 读写的对象，也是页面上那张可拖拽的图**。左栏点「接线」打开全页画布。

## 用起来是什么样

板卡按实物画：引脚分成左右两列，顺序就是板子上的上下顺序。ESP32-DevKitC V4 左边 3V3/EN/GPIO36… 到 5V，右边 GND/GPIO23… 到 GPIO6（含 6 个接内部 flash 的脚）；常见 30 脚兼容板则是 15+15，没有那 6 个脚。

- 拖部件标题 = 挪位置（只改布局，不改语义）
- 从一个引脚圆点拖到另一个引脚 = 连一条网络
- 圆点是空心的 = 这个脚还空着；**实心 + 网络颜色** = 已经接了线，鼠标悬停能看到接到哪张网络
- 引脚放哪一列由你定：点部件 → 每个引脚一行，点「左/右」换边、↑↓ 调顺序。模板给的是默认值，你改过的部件会记成「手动排版」，不再自动翻转，也不再被「一键整理」重新分边
- 线从引脚侧面引出、以贝塞尔曲线落到另一个引脚（Fritzing 那种画法），画在卡片**上层**并带一圈白色衬底：穿过卡片时也看得见，不会为了躲卡片绕一大圈
- 模块的**整体**朝向会自动判断：它连着谁，排针就转向谁。点部件 → **⇋ 翻转** 覆盖，**↺ 自动** 恢复；开发板始终按官方左右布局
- 一张网络接很多脚时按**树**布线（最短生成树），GND 这种大网络不会从一个点放射成蜘蛛网
- 点线 = 选中（线的命中区有 14px 宽，不用瞄准那 2px）；选中后其它线自动变淡，方便看清这一根
- 组件标题前面有图标（🎤 麦克风、🔊 喇叭…），库里的型号自带；自定义部件点开详情 → 「图标」下拉可以自己选
- 复制：点标题栏右侧的 `id` 直接复制 id；详情里的「复制」按钮复制名称或 id
- 点部件标题（不拖）或点诊断里的「定位」= 看详情
- `Delete` 删掉选中的网络，`Esc` 取消当前操作，滚轮缩放
- 顶栏「一键整理」= 在不打乱你画的左右关系的前提下排整齐：**开发板固定在原地不动**；其它部件留在"原来在板子左边还是右边"，按远近吸附成列（固定列距），**列里的卡片会上下挪到跟它连的那个引脚同一行**——所以 N20 会贴到 MX1508 的输出脚上、功放会对准它的 GPIO，不会吊在半空；同列卡片再依次往下码，绝不重叠；**每个模块的引脚按线的走向拆到左右两边**——电池接进来的 VIN 画在左边缘、去电机/负载的 OUT 画在右边缘；没接线的脚先找同名的另一半（`B+` / `B−`、`VIN+` / `VIN−`、`P1` / `P2`）跟过去，再不行才跟相邻引脚。地线这种到处都连的网络**不参与判断**，否则充电板那颗 `B−` 会被板子另一头的 GND 拽到右边、线又绕回卡片外面。分边读的是你当前画布的左右关系，所以你原来的思路会保留，只是变整齐
- 顶栏「诊断」显示校验结果，点「定位」跳到出问题的部件或网络

## 拍照加硬件

把模块的照片贴进聊天，模型认出型号和引脚后会用 `add_part` 建一个 `source: "photo"` 的部件：

- 部件标题上会出现 **照片?** 标记，诊断里有一条 `photo-unverified` 警告
- 点开部件详情能看到每个引脚的 role、电压、在哪一侧；核对过实物后点 **「标记引脚已核对」**，标记变 **照片✓**，警告消失
- 识别错了就改：让它用 `update_part` 重写 `pins`，或删掉重加

识别这一步不自动信任是有原因的：DHT22 有 3 脚/4 脚两种封装，SSD1306 有 4/6/7 脚，接反一次后面固件全废。

## 文件在哪

**一个工作区可以有多个接线项目**：每个放了 `hardware/wiring.json` 的目录就是一个项目，文件跟着它所在的那个仓库/固件目录走，可以提交进 git，改坏了直接回滚。

- 打开页面时会扫一遍工作区（最多 6 层，跳过 `node_modules`、`.git`、`dist`、`build` 这些），把找到的项目列在顶栏的项目下拉里，形如 `firmware/sensor · 1板/3网`；`. ` 表示工作区根目录那份
- 顶栏右边显示这个工作区一共识别到 **N 个项目 / M 块板**（板 = 文件里 `kind: "board"` 的部件）
- 切换项目就是切换画布；两个项目各写各的文件，互不影响
- 「＋ 新项目」可以在任意子目录里创建一份新的，顺便选初板卡；目录不存在会自动建

```json
{ "version": 1, "rev": 12, "meta": { "title": "我的接线", "board": "ESP32 DevKitC" },
  "parts": [ { "id": "mcu", "model": "esp32-devkitc", "kind": "board", "pins": [ ... ] } ],
  "nets": [ { "id": "n3", "name": "DHT_DATA", "kind": "signal", "nodes": ["mcu:GPIO4", "dht:DATA"] } ],
  "pending": [] }
```

`pins` 在添加部件时从型号模板拷进项目，所以库更新不会偷偷改你的项目；照片/手册认出来的自定义硬件直接写 `pins` 数组即可。`at` 只是画布坐标，Agent 不需要碰。

## Agent 怎么用

工具 `hardware_map`，和页面走同一条写入路径、同一套校验：

| action | 作用 |
|---|---|
| `list` | 列出工作区里所有接线项目，各自几块板、几个网络 |
| `read` / `check` | 返回部件、网络、未连接引脚、校验结果，不写文件 |
| `add_part` | 加板卡/模块（`model`），或自定义 `pins` |
| `connect` / `disconnect` / `unlink` | 连线、删网络、把单个引脚从网络里摘掉 |
| `set_net` / `move` / `flip` / `set_pin_sides` / `set_meta` | 改网络属性、摆位置、左右镜像部件、把指定引脚换到另一条边、改项目标题 |
| `propose` | 把一批改动挂成「建议」，页面顶部出现「应用 / 忽略」 |
| `apply_pending` / `discard_pending` | 应用或忽略建议（你说「按这个改」时它才调） |

`project` 参数可以传工作区相对路径（`"firmware/sensor"`）、工作区 id，或绝对目录；不传时**从会话当前目录往上找最近的 `hardware/wiring.json`**，所以在 `firmware/sensor` 里干活时默认改的就是这个项目的接线。

节点写法是 `部件id:引脚名`，例如 `mcu:GPIO4`、`dht:DATA`。ESP32 板卡模型是 `esp32-devkitc`；模块库有 dht22、dht11、bme280、mpu6050、ssd1306、bh1750、hcsr04、sg90、relay、neopixel、sdcard、led、button、potentiometer、buzzer。

## 校验什么（以及不校验什么）

会报错的：未共地、地分散在多个网络、5V 加到耐压 3.3V 的引脚、电源网络混接不同电压、同一网络两个输出对打、引脚同时出现在两张网络、引用了不存在的引脚。

会警告的：启动配置脚（GPIO0/2/5/12/15）、UART0 占用（GPIO1/3）、I2C 没标上拉、模块供电不足、只有一个引脚的空网络、照片识别的引脚还没核对。

**不校验**：电流预算、线径、EMI、器件真实封装、电平转换器的存在。它是连接关系的记录，不是电气审查；别把它当成「接了就一定不炸」。

## 支持的板卡

| 型号 | 引脚 | 来源 |
|---|---|---|
| `esp32-devkitc` | 38（19 / 19） | Espressif DevKitC V4 J2/J3 表 |
| `esp32-devkitc-30` | 30（15 / 15） | 常见 30 脚兼容板（省掉 flash 脚） |
| `esp32-c3-devkitc-02` | 30（15 / 15） | Espressif J1/J3 表 |
| `esp32-c3-devkitm-1` | 30（15 / 15） | Espressif J1/J3 表 |
| `esp32-c3-supermini` | 16（8 / 8） | 常见 16 脚丝印 |
| `esp32-s3-devkitc-1` | 44（22 / 22） | Espressif J1/J3 表（v1.1） |

换板子不用删了重画：让 Agent 调 `update_part` 时给 `patch.model`，同名引脚（3V3、GND、GPIO4…）上的线自动留着，新板上没有的引脚会把对应的线一起丢掉，并在返回里说明。名字如果还是模板名，会跟着新板卡改；你自己改过的名字不动。

## 边界

- 板卡引脚按官方 header 表录入，但**不同批次/厂家可能丝印不同**（尤其 SuperMini 克隆板）；接线前对一眼实物。
- 照片识别是 Agent 那一侧的事：把照片贴进聊天，模型认出引脚后调 `add_part`。认错了会连错，所以识别结果建议走 `propose` 让你先确认。
- 页面和 Agent 同时改同一个文件时，用 `rev` 兜底：过期写入会提示「刚被别处改过」，不会静默覆盖。
